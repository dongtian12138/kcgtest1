# 旋拧控制与实验效率修复

2026-09-13。用户已要求实施前述问题，并把自由空间第七关节返回与现实耗时列为重点。模型几何、质量、原始接触和独立传动/腕力边界保留。以下软件修改已接入；物理效果需要本轮短验证，不能以软件测试代替装配成功。

## 已实施

1. 保留名义关节轨迹积分，末端位姿纠正改用实际编码器位姿。超出有限横向误差范围时停转进入可恢复处理；关节速度采用整体缩放，避免逐关节裁剪改变指令方向。
2. 将期望抓持关系与当前视觉观察分开。期望关系用于纠正实际手部偏差，当前图像用于连接器位置、轴线、导向/避碰与进度。不能用刚观察到的偏移重定义期望抓位，把误差自动消掉。
3. 轴向采用已知7.62 mm导程的名义运动加有界力修正，修正有恢复项与0.1 mm范围，合成速度仍受原0.3 mm/s上限限制。
4. 旋拧时重新读取当前RGB-D，识别观察到的进展、无进展、滑移/卡滞线索和到位候选；到位候选经连续确认后停止运动，最终装配仍由独立物理评价决定。
5. 夹紧使用现有末段0.25秒数据检查均值误差、波动和剩余传动余量。未满足就绪要求则明确退出，不自动延时加力。手指调节/卸载统一新版底座力矩补偿与换算来源。
6. 加入同回合有限恢复：可恢复偏载停转后，用当前视觉检查导向，真实卸载、张手、回转与重抓，只继续尚未发送的角度。原失败记录保留，硬故障不恢复，物体状态不回写。
7. 空手返回优先只改变第七关节目标，其他六个关节目标保持。全轨迹检查碰撞，末尾检查实际角度；90°、1 rad/s、2 rad/s²的规划时长约2.071秒。是否在现有场景可直接执行，以局部检查为准。
8. 接触路径解码缓存；每步仅更新变化的驱动量，复用同一物理时刻的机器人读数；数值记录使用保留NaN/Inf失败读数的C JSON编码，并减少归档时整条记录的复制和高压缩成本。原始物理记录不抽掉。新增分项计时区分原生步进、接触回调、机构更新、读取和归档。
9. 同回合视觉身份与相机资源复用，当前深度图重新拟合位置/轴线；区域或质量不满足时重新完整识别。三个已保存真实RGB-D帧的离线回放与原完整识别的位置结果一致到浮点精度，后两帧拟合约0.13秒；这不等于已验证所有新视角。
10. 动态入口加入现实时间限制，默认总上限300秒，预留30秒受控收尾，并由外部进程组截止保护。加载、计算、观察、保存均计入，不临时延长。诊断读取指定源时刻改用原始记录块索引。

JSON依赖采用[PyPI官方ujson 5.13.0发布](https://pypi.org/project/ujson/5.13.0/)，已安装到项目离线环境与Isaac环境，并写入依赖文件。此处选择的数值编码路径保留原JSON对非有限失败读数的表达；已验证浮点回读与原始数组格式。
